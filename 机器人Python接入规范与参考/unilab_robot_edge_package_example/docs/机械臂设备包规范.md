# Uni-Lab 机械臂 Edge 设备包规范

版本：0.1
适用对象：通过 Python/TCP、厂家 SDK 或受控 ROS2 Adapter 接入 Uni-Lab edge 的工业/
协作机械臂。

## 1. 目标与非目标

设备包的目标是让不同厂家机械臂在 Uni-Lab 中具备同一组可验证行为：

1. 只有在身份、控制权、安全状态、许可、工具、负载和部署版本正确时运动。
2. 相同物理命令至多下发一次；回复丢失时进入 `UNKNOWN`，禁止自动重发。
3. 普通取消能够转换为厂家受控停止，并确认机器人已停稳。
4. 成功必须有命令级 Completion Witness，不能把 Socket 写成功当成动作完成。
5. 日志可以关联命令、Resource、Site、技能、程序、点位、工具、负载和控制器终态。
6. 厂家协议、单位、端口、SDK 和反馈格式只存在于 Robot Connection。

设备包不是：

- 安全 PLC、机器人安全控制器或安全认证软件；
- 实时碰撞检测器；
- 第二套 OS Scheduler；
- 任意 `MoveJ/MoveL/pose/joint/script` 的 Workflow 透传层；
- 物料数据库。

## 2. 责任分层

```text
Uni-Lab Workflow / Scheduler
业务顺序、Resource/Site、任务级资源锁
                  │
                  ▼
RobotEdgeDriver
Profile动作、Site解析、幂等、许可、日志、停止、对账
                  │ Robot Connection Interface
                  ▼
厂家 Adapter / Cell Controller
协议、单位、控制器程序、完成见证、普通运动许可
                  │
                  ▼
机器人控制器
已验证程序、点位、轨迹、实时运动

独立安全系统
急停、安全门、安全区、安全速度、人员保护
```

滑轨、多机器人、重叠工作区和动态设备干涉属于 L2 单元协调场景。Scheduler 的
`robot_cell` 资源锁只能做任务级粗互斥，最终进区许可必须由 Cell Controller、PLC 或
机器人协调控制器提供。Motion Permit 是许可的只读镜像，不构成安全功能。

## 3. Edge Package 结构

必须至少包含：

| 文件 | 责任 |
|---|---|
| `pyproject.toml` | Python 3.11+、依赖、`unilabos.drivers` entry point |
| `profile/package.yaml` | ProfileV1、driver key、connection ref、资源拓扑和 driver 配置 |
| `profile/device.yaml` | DeviceSpecV2 动作 Interface、结果、资源、超时和恢复语义 |
| Python package | Runtime Driver、配置解析、日志和厂家 connection Interface |
| 配置 | Interaction Profile 与 Point Set |
| 测试 | 无真机幂等、许可、UNKNOWN、停止、对账、Schema 测试 |
| 文档 | 动作、点位、厂家 Adapter 与 SAT 规范 |

发现链路必须完整：

```text
pip install package
→ importlib.metadata: unilabos.drivers
→ ProfileV1.default_device_binding.driver_key
→ BasicConfig.runtime_connections[connection_ref]
→ RobotEdgeDriver(plc=connection, driver_config=...)
```

`plc` 是当前 Uni-Lab Profile composer 的构造参数名；对机械臂包而言，它实际承载
Robot Connection，不表示普通 PLC 具备安全等级。

## 4. Uni-Lab 可见动作

### 4.1 生产动作

#### `pick`

| 参数 | 提供者 | 说明 |
|---|---|---|
| `resource` | Workflow/资源图 | 必须含稳定 ID、类型、父载体和当前 Site |
| `command_id` | OS Runtime | 物理命令幂等键，不由实验作者手填 |
| `source_boot_id` | OS Runtime | 调用源启动周期 |
| `monotonic_sequence` | OS Runtime | 同一启动周期严格递增 |
| `parameters` | Workflow | 仅 Interaction Profile 声明的有界修正 |

设备包从 `resource.location.parent_id + resource.location.site + pick` 解析
Interaction Profile。

#### `place`

除命令信封外只增加：

| 参数 | 说明 |
|---|---|
| `target_mount_resource` | 目标 Warehouse、Rack 或工位载体 |
| `target_site` | 目标载体内 Site |

目标位置尚未成为 Resource 的 parent，不能从 Resource 推导，因此必须显式表达。
`target_device` 应由目标载体的资源归属推导，不应成为机械臂动作重复参数。

`pick/place` 只执行物理取放。完整搬运顺序是：

```text
robot.pick
→ robot.place
→ host.transfer_resource
```

只有最后一步修改 OS ResourceTreeSet。若物理放料成功但记账失败，应补偿/对账记账，
不得重放机械臂动作。

### 4.2 调试动作

调试必须先建立 Commissioning Session。会话冻结：

- 机器人/控制器 boot；
- Point Set 与 calibration version；
- tool/TCP；
- payload；
- 外部轴/滑轨上下文；
- 速度上限；
- 到期时间。

任一项变化，会话立即失效。`move_to_point` 每次只变化：

- `point_ref`；
- 允许的 `move_j/move_l`；
- 不超过点位和会话上限的速度；
- 指定坐标系且有界的 offset；
- OS 命令信封。

调试动作不接受任意 pose/joint，不自动改变库存，不隐含使能/清警/复位。

### 4.3 查询、停止和对账

- `query_status`：只读状态和许可摘要。
- `get_command`：读取持久日志，不接触控制器。
- `reconcile`：只读控制器证据并更新已有命令，绝不重新执行。
- `request_controlled_stop`：走独立停止能力，不等待普通动作资源锁。

急停不由该动作实现。急停触发、复位和安全恢复仍由现场安全系统及维护流程负责。

## 5. Resource、Site、Interaction Profile 和 Point

四者不能混用：

| 概念 | 回答的问题 | 权威位置 |
|---|---|---|
| Resource | 搬什么、归谁、当前 parent 是谁 | Uni-Lab ResourceTreeSet |
| Site | 载体上的哪个稳定位置 | Warehouse/Rack/工位资源模型 |
| Interaction Profile | 在该 Site 如何完成 pick/place | edge 部署配置 |
| Point | 特定机器人上下文中的一个已部署运动点 | 机器人控制器 + Point Set 镜像 |

一个 Site 可以有多个 Interaction Profile，例如不同的 `pick/place`、工具、负载或标定
版本。几何和运动约束完全相同时才可复用同一 Profile。

换工具点归 Tool Station/Tool Site，不复制到每个物料 Site。Workflow 可以编排
“还工具 → 取工具 → Site Action”，但点位所有权不随编排转移。

阵列点允许由已审核锚点离线物化；部署后必须有确定内容哈希。生产运行时只引用版本和
槽位，不临时生成无界位姿。

## 6. 状态与完成见证

至少分别表示：

- connection：`DISCONNECTED/ONLINE`
- control authority：`MANUAL/LOCAL_AUTO/REMOTE_AUTO/UNKNOWN`
- safety：`NORMAL/REDUCED/PROTECTIVE_STOP/ESTOP/FAULT/UNKNOWN`
- operational：`IDLE/EXECUTING/PAUSED/FAULT/UNKNOWN`
- command：`VALIDATED/DISPATCHING/SUCCEEDED/FAILED/CANCELED/REJECTED/UNKNOWN`

生产成功的 Completion Witness 至少包含：

```yaml
controller_command_id: 厂家命令或程序实例标识
observed_at: 独立状态观测时间
final_state: 控制器确认的终态
```

实际项目还应加入最终锚点/位置、夹具状态、物料存在传感器、状态帧序号、控制器 boot
和错误码。只返回 `0`、`accepted`、`sent` 或 ROS Goal accepted 不足以判成功。

## 7. 幂等、重启和 UNKNOWN

1. `command_id` 与请求指纹一起持久化。
2. 相同 ID、相同请求返回已有记录，不再次下发。
3. 相同 ID、不同请求直接拒绝。
4. 写入 `DISPATCHING` 后发生的未知异常一律记为 `UNKNOWN`。
5. edge 进程重启时，未完成的 `VALIDATED/DISPATCHING` 命令转为 `UNKNOWN`。
6. 同一 `source_boot_id` 的 `monotonic_sequence` 必须严格递增。
7. `UNKNOWN` 只能 `get_command/reconcile/request_controlled_stop`，不得执行重试。

当前 Profile runtime 尚未自动注入 `run_id/node_id/boot_id/sequence`。在 OS 补齐
execution context 注入前，设备动作 Schema 必须保留这些运行态字段；上层 UI 不应要求
实验作者填写它们。

## 8. Robot Connection Interface

现场连接必须实现：

```python
read_status()
read_motion_permit()
execute_skill(request)
execute_point(request)
controlled_stop(command_id, reason)
reconcile(request)
```

约束：

- 同步和异步实现都允许，driver 会隔离阻塞调用。
- `execute_*` 一次调用至多下发一次物理动作。
- 明确未开始时抛 `RobotRejected`。
- 明确失败终态时抛 `RobotMotionFailed`。
- 可能已下发但结果不明时抛 `RobotResultUnknown`。
- `controlled_stop` 必须使用不被阻塞运动占用的控制路径，并验证停稳。
- `reconcile` 只能查询，不得调用运动函数。

### 8.1 厂家映射要求

| 厂家路径 | Adapter 必须补齐的证据 |
|---|---|
| DOBOT V4 | 响应 CommandId、30004 CurrentCommandId、RobotMode、实际位置 |
| DOBOT V3 | `Sync()` 加状态/实际位置复核 |
| Elite EC/EA | JSON-RPC ID、机器人/轨迹终态、实际位置 |
| Elite CS/ES | RTSI、寄存器握手或官方 SDK 完成回调；30001 写成功不算完成 |
| DUCO | `ST_Finished(4)` 加状态/位置复核；`-1` 和通信异常进入 UNKNOWN |
| FAIRINO FR5 | 一次性下发封装、新鲜状态流、队列/位置终态；绕开 SDK 静默重试 |

所有单位只在 Adapter 内转换一次。厂家 SDK 自动重试运动时，必须改为一次性发送路径或
由更低层命令通道替代，不能原样接入。

## 9. ROS2 接入

Uni-Lab edge 已有 ROS2 context 时：

- 复用 OS 注入节点和 executor，不再次 `rclpy.init()`；
- launch 必须有唯一 owner、命名空间、ready 门禁、退出监控和受控清理；
- ROS2 Adapter 仍须满足同一 Robot Connection Interface；
- MoveIt/RViz/fake hardware 可验证模型和规划，但不是完成见证或真机许可；
- `ros2_control` 读写失败必须向上返回失败，不能总是 `OK`。

当前 Profile runtime 通过 `BasicConfig.runtime_connections` 注入 live connection，
没有 `post_init(ros_node)`。因此 ROS2 launch/node 生命周期应由 edge 部署层创建后再
注入，或使用支持 `post_init` 的 decorated device 形态；不要在本 driver 中私自创建
第二个 ROS executor。

## 10. 验收门槛

### 离线

- ProfileV1/DeviceSpecV2 可加载；
- entry point 可发现；
- YAML、Python 编译和单元测试通过；
- 许可缺失默认拒绝；
- 相同命令不重复执行；
- ID 冲突、序号倒退拒绝；
- 模拟丢回复后保持 UNKNOWN；
- reconcile 不增加 execute 计数；
- Point Set 未批准时不能建立调试会话。

### SIL/仿真

- 与真机相同动作 Schema；
- 工具、TCP、负载、外部轴和点位版本可验证；
- 超时、断线、重启、取消和状态陈旧故障注入；
- 工作站碰撞体、夹具和物料模型齐全后再声明 S2/S3。

### 真机首件

1. P0：铭牌、SN、控制器/软件、IP、TCP、负载、安全回路。
2. P1：只读连接、状态新鲜度、控制器重启识别。
3. P2：空载、最低批准速度、两个直接示教点 A→B→A→park。
4. P3：动作中取消、丢回复、断网、edge 重启和控制器重启。
5. P4：两个测试 Site、假物料、夹具和物料传感器见证。
6. P5：全槽位、阵列、换工具、带料和异常恢复 SAT。

未完成现场风险评估、急停验证和安全验收时，不得无人值守运行。
